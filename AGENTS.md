# AGENTS.md

## Project Overview

Frontend client for a personal book library collection management system (Warhammer 40k, story, tech, and history books). This repo is the React SPA only. Still early-stage: no backend API integration yet — however a settings page exists (`/settings`) where users can save their name and an optional Google Books API key (for future out-of-library searches), persisted to `localStorage` under `library-collection:settings`.

## Related Repo / Backend

- **Library-collection-server**: https://github.com/Battlertrunks/Library-collection-server
- GraphQL API backed by SQLite3, CORS enabled, served at `http://localhost:3000/graphql` (GraphiQL available).
- Also uses pnpm. Future client work will fetch from this API.

## Tech Stack

- **React 19** with the React Compiler — enabled via `react({ compiler: true })` in `vite.config.ts`, powered by the Rust-based `oxc-transform-react` (NOT `babel-plugin-react-compiler`)
- **TypeScript 7** (~7.0) — strict mode, `verbatimModuleSyntax`, `erasableSyntaxOnly` (no enums/namespaces), `noUnusedLocals`/`noUnusedParameters`
- **Vite 8** — dev server, build tooling
- **TanStack Router v1** — file-based routing; `src/routeTree.gen.ts` is auto-generated by `@tanstack/router-plugin` (never edit manually)
- **Tailwind CSS v4** — via `@tailwindcss/vite` plugin
- **Vitest 4** — tests run in jsdom with setup at `src/test-setup.ts`
- **ESLint 10** (flat config, `eslint.config.js`) + **Prettier** (`.prettierrc`)

## Commands

Package manager is **pnpm** — never use npm.

```sh
pnpm dev          # start Vite dev server
pnpm build        # typecheck (tsc -b) then build (vite build)
pnpm lint         # ESLint over the whole project
pnpm test         # Vitest (watch mode); use `pnpm vitest run` for CI
pnpm preview      # preview the production build
```

## Project Structure

```
src/
  routes/            # TanStack Router file-based routes
  components/
    <page>/          # feature folders, e.g. search/, home-page/, library-page/, settings-page/, series-page/
      Component.tsx
      Component.css  # colocated plain CSS (BEM-style class names)
      Component.test.tsx
  types/             # shared types (e.g. SelectOptions.ts)
  main.tsx           # entry: createRoot -> <App />
  App.tsx            # createRouter({ routeTree }) + RouterProvider
  index.css          # global styles
  test-setup.ts      # sets IS_REACT_ACT_ENVIRONMENT
```

- Routes in `src/routes/` are thin wrappers: `createFileRoute` + render the page component from `src/components/`.
- Page components live in feature folders under `src/components/<page-name>/`.
- New routes are auto-registered into `routeTree.gen.ts` by the router plugin on dev/build.

## Code Conventions

- **Prettier**: double quotes only (`.prettierrc` sets `singleQuote: false`). Format edits with Prettier.
- **Type-only imports**: `verbatimModuleSyntax` is enabled — always use `import type { ... }` for types.
- **Strict TS**: no unused locals/parameters; no enums or namespaces (`erasableSyntaxOnly`).
- **Imports**: relative paths; no path aliases configured.
- **Styling**: Tailwind utility classes in JSX plus colocated plain CSS files using BEM-style class names (e.g. `filter-modal__backdrop`, `filter-modal__btn--primary`).
- **React Compiler** is active — follow Rules of React (Hooks rules) as enforced by the compiler.
- **Accessibility**: modals/dialogs use `role="dialog"`, `aria-modal`, and `aria-label` attributes.
- **Dark mode**: theme is a `"light" | "dark"` value in `UserSettings` (see `src/components/settings-page/useSettings.ts`); dark mode is toggled by adding/removing the `dark` class on `document.documentElement`. An inline script in `index.html` applies the saved/system theme before React mounts to avoid a flash — treat it as a temporary fix until a more permanent solution lands.

## Testing Conventions

- Vitest + jsdom; `src/test-setup.ts` sets `IS_REACT_ACT_ENVIRONMENT = true`.
- Tests are colocated next to components as `*.test.tsx` (e.g. `FilterModal.test.tsx`).
- **No Testing Library installed** — tests use `renderToString` from `react-dom/server` and `createRoot`/`act` from `react-dom/client` directly. Don't add tests that require Testing Library.
- Example pattern: render with `createRoot` inside `act()`, query the DOM with `container.querySelector`, unmount in `afterEach`.
